**작업은 이렇게 구성됩니다**

Round · 하나의 목표를 다루는 작업 단위\
│　**[사용자가 생성 결정]**\
└─ Work · 목표 안에서 나누는 과제 (선택)\
　 │　**[사용자가 요청하거나 AI가 생성]**\
　 └─ Step · 실제로 진행할 실행 단계 (필수)\
　 　 │　**[AI가 작성 · 사용자가 조정·지정 가능]**\
　 　 └─ Task · 실행을 위한 세부 작업 (선택)\
　 　 　 　 **[AI가 구성·관리]**

Work가 필요 없으면 **Round → Step**으로 구성합니다. Task도 필요할 때만 사용하므로, 간단한 작업은 Round와 Step만으로 충분합니다.

**Round와 하위 Round, Work의 관계**

Round\
├─ 하위 Round · 별도로 구획한 작업 단위\
│　 **[사용자가 생성 결정]**\
│　 └─ Step 또는 Work → Step\
└─ 하위 Round · 별도로 구획한 작업 단위\
　　**[사용자가 생성 결정]**\
　　└─ Step 또는 Work → Step

- **하위 Round**는 AI가 분리를 제안할 수 있지만, 생성은 사용자가 결정합니다. 하위 Round 아래에 다시 하위 Round를 만들지는 않습니다.
- **Work**는 이미 정한 Round 범위 안에서 과제를 나눌 때 사용합니다. AI가 만들면 이유와 담당 범위를 안내합니다.

각 단위마다 별도 파일을 만들 필요는 없습니다.

**예시 — 알림 설정 개선**

Round · 알림 설정 개선\
├─ Work · 설정 화면\
│　 ├─ Step · 화면 기준 정리\
│　 └─ Step · 화면 구현\
├─ Work · 설정 저장 API\
│　 ├─ Step · API 기준 정리\
│　 └─ Step · API 구현\
│　 　 ├─ Task · 설정 조회 처리\
│　 　 └─ Task · 설정 저장 처리\
└─ Step · **라운드 정합성 점검**

사용자가 Round를 정하면 AI는 필요에 따라 과제를 나누고 실행 단계를 작성합니다.

정합성 점검은 **작업서의 변경 내용이 기준서에 반영됐는지, 기준서와 코드가 잘 연결되어 있는지** 확인합니다. 코드 동작 테스트와는 별개입니다.

**운영 방식은 두 가지입니다**

**① 일반형 — 기능별로 Round를 진행**

Round · 알림 설정 개선 → **[라운드 점검]**\
Round · 검색 개선 → **[라운드 점검]**\
Round · 결제 개선 → **[라운드 점검]**

각 Round 종료 시 해당 범위를 점검하고, **종료된 Round가 5개 쌓일 때마다 전체 점검을 안내**합니다. 하위 Round도 횟수에 포함됩니다.

**② 스프린트형 — 여러 작업을 하나의 기간·목표로 묶어 진행**

Round · 이번 스프린트\
├─ 하위 Round · 알림 설정 개선 → **[라운드 점검]**\
├─ 하위 Round · 검색 개선 → **[라운드 점검]**\
└─ Step · **전체 정합성 점검**

하위 Round마다 해당 범위를 점검하고, **최상위 Round 종료 시 전체를 점검**합니다.

운영 방식은 나중에도 변경할 수 있습니다.
