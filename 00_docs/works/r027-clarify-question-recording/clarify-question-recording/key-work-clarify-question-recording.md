# 질답 기록과 질문 변경 규칙 작업서

## Goal

질답 도중 세션이 끊겨도 사용자가 이미 설명한 답변을 다시 구성하지 않도록 질문별 기록을
보존한다. 명확한 답변에 불필요한 확인을 요구하지 않고, 해석이 필요한 답변만 확인한다.
질문 변경 이력과 파생 관계를 남기되 기록·읽기·상태 관리 비용을 필요한 범위로 제한한다.

## 생성 근거와 권한

2026-10-12~13 대화에서 사용자는 Clarify의 회색 영역을 검토하고 아래 방향을 합의했다.
최초 2026-10-13 요청은 라운드 생성이었으며 생성과 실행을 분리했다. 이후 같은 날 사용자가
구현 진행을 요청하여 S01 기준 정합화 → S02 스킬 반영 → S03 검증을 시작한다.
정확한 과거 답변 시각을 재구성하거나 소급 Q&A 로그를 만들지 않는다.

## 합의한 동작

1. **최초 생성:** 기록 대상 질답은 최초 시작 시 문서를 만든다. 첫 답변이나 그룹 종료까지
   문서 생성을 미루지 않는다. 대주제별 한 파일과 함께 적용할 문서 범위별 그룹을 유지한다.
2. **질문별 저장:** 질문 하나의 답변을 처리하면 해당 기록의 저장·확인까지 마치고 다음
   질문으로 넘어간다. caller의 전달만으로 저장을 완료한 것으로 보지 않는다.
3. **명확한 답변:** 예·아니요, 선택지 지정 등 현재 대화에서 의미가 명확한 답변은 의도를
   다시 묻지 않고 즉시 확정·저장한다.
4. **해석이 필요한 답변:** 주고받은 대화를 요약·추리·분석하여 새 문장으로 구성해야 한다면
   해석 내용을 보여 주고 의도를 확인한다. 사용자에게 제시한 해석은 확인 대기로 임시 저장하고,
   확인 후 확정 답변으로 저장한다. 확인 전 해석을 확정 결정이나 원문 적용 근거로 사용하지 않는다.
5. **질문 구조 변경:** 폐기와 추가만 사용한다. 기존 질문을 덮어쓰거나 삭제·재번호화하지 않는다.
   변경은 기존 질문 폐기와 새 질문 추가로 표현한다. 폐기된 질문의 답변란에는 폐기 이유와
   원인이 된 질문을 연결한다. 폐기 설명을 사용자가 실제로 한 답변처럼 표현하지 않는다.
6. **파생 추가:** Q01 답변에서 추가 질문이 생기면 Q01을 유지하고 새 질문을 추가한다.
   `Q01-A`, `Q01-B`처럼 Round의 대문자 영문 suffix 방식으로 관련 질문을 식별하고,
   문서에서도 관련 질문 가까이에 둔다. 변경으로 생긴 질문과 단순 파생 질문을 모두 지원한다.
7. **범위:** 원 질문 범위를 벗어나도 전체 질답 주제 안의 파생 질문은 생성 이유를 밝히고
   하나씩 진행할 수 있다. 전체 주제나 승인된 작업 범위를 넘어가면 별도 처리 범위를 확인한다.
   파생 번호만으로 같은 결정 또는 같은 문서 적용 그룹이라고 판단하지 않는다.
8. **확정 답변 변경:** 이전 답변을 조용히 덮어쓰지 않고 새 질문·답변에 변경 이유와 이전
   질문을 연결한다. 미응답 질문의 폐기와 확정 결정의 번복을 구분하고, 이미 반영한 문서에
   미치는 영향은 별도로 확인한다.
9. **선택적 읽기:** 질답 문서는 작업 기록이다. 새 세션 시작이나 일반 진행 상태 조회를
   이유로 매번 읽지 않는다. 중단된 질답의 맥락 복구, 현재 대화에 없는 과거 답변·결정 확인,
   사용자 요청에 필요할 때만 관련 부분을 읽는다. 충분한 대화 맥락이 있으면 다시 읽지 않는다.
10. **재개:** 기록을 읽어 복구해야 하는 경우 확정 답변은 반복 질문하지 않는다. 확인 대기
    해석은 설명을 다시 요구하지 않고 확인부터 이어가며, 폐기 질문을 미응답으로 처리하지 않는다.
11. **문서 없는 질답:** 중요성이 낮고 후속 작업·결정의 근거로 남길 필요가 없는 질답은
    대화로 진행할 수 있다. 중요성 판단과 일반 질답·Clarify 경계를 기준에 명시한다.
12. **책임 분리:** Clarify는 질문과 해석·handoff를 맡고 caller가 Author를 통해 기록한다.
    질문별 저장과 그룹 종료 후 원문 반영을 분리한다. 질답 로그 자체는 원천 정책·수락 근거가 아니다.

## Scope와 예상 적용 위치

- Project의 clarification log 규칙, Clarify·Author 기준과 스킬 source를 정합화한다.
- Reader 등 소비자의 기록 읽기 안내가 위 규칙과 충돌할 경우 해당 안내만 최소 수정한다.
- 실제 영향을 받는 계약 검사와 중단·복구·파생 질문 시나리오를 검증한다.
- 기존 질문별 저장·그룹별 원문 적용 구분, 한 번에 한 질문, 문서 작성 소유권을 유지한다.

### 제외

- 전역 설치·배포, commit 및 계획 밖 코드 구현
- 다른 Round 상태 변경, 상태 통합 runtime 전환, 기존 질답 로그 일괄 변환
- 새 DB·인덱스·자동 질문 엔진, 필수 평가 점수·그룹 완료 상태·전수 대화 복제
- 승인되지 않은 범위의 파생 질문 자동 수행이나 사용자 판단의 추정 확정

## S01에서 구체화한 세부사항

- 재파생도 기본 질문 아래 한 단계 대문자 suffix를 사용하고 직접 원인을 연결한다.
  Round 작명 규칙과 기존 ID 보존을 따르는 구현 기본값이다.
- 별도 상태 필드를 추가하지 않고 답변 안의 `[확인 대기]`·`[폐기]`로 구분한다.
  답변일시는 실제 답변·확인 시각이며 과거 시각이 없으면 `미상`으로 둔다.
- 중요한 기록의 작업서·승인된 위치가 없으면 caller에 위치·권한 미해결을 반환한다.
  자동 Work 생성·임의 위치 선택·중요 질답의 무기록 우회는 하지 않는다.
- 매 답변 저장과 대상 entry 재읽기 뒤 다음 질문을 한다. 저장 실패는 같은 entry로 재개하고
  이미 저장된 handoff 재전달은 중복 추가하지 않는다.
- 문서 없는 대화가 중요해지면 필요한 기존 맥락만 보존하며 기록을 시작한다.
- 근거와 기준 변경 전후 의미: `key-progress-contract.md`.

## Step 계획

### R027/S01 — 질답 기록 계약과 기준 정합화

- **Goal:** 합의한 동작과 남은 세부사항을 구현 가능한 일관된 계약으로 정리한다.
- **Scope:** 관련 Project·Clarify·Author 기준, 필요한 Reader 안내, 기록 형식과 중요성 경계.
- **Source Context:** 위 Source Context, 합의한 동작과 실제 기존 기록 사례의 필요한 부분.
- **Completion Criteria:** 질문별 저장, 조건부 의도 확인, 폐기·추가·번호·선택적 읽기가
  충돌 없이 정의되고 production 구현 전 기준 정합화를 수락하거나 no_change 근거가 있다.
- **Stop Conditions:** 미해결 사용자 선택, 기록 권한·민감정보·전체 주제 범위 확대가 필요하다.
- **Verification:** 명확한 답변, 해석 필요 답변, 폐기·단순 추가·답변 번복, 기록 없는 질답을
  계약에 대입하고 기존 금지 조항과의 충돌을 확인한다.
- **Expected Output:** 정합화된 기준, 해소된 세부 경계, S02 최소 대상과 검증 기대값.

### R027/S02 — Clarify·Author 계약 반영

- **Goal:** 질문별 기록을 저장까지 닫고 불필요한 확인과 반복 읽기를 피하는 스킬을 제공한다.
- **Scope:** Clarify·Author skill source와 확인된 최소 소비 안내·관련 contract 검사.
- **Source Context:** 수락된 S01 기준과 실제 repository skill 계약.
- **Completion Criteria:** 각 합의 규칙이 질문 담당·저장 담당·소비자 사이에서 일치한다.
  소비 프로젝트에 이 저장소의 개발 기준서를 요구하지 않는다.
- **Stop Conditions:** 미승인 코드·상태 저장 구조 변경, 외부 서비스 또는 일괄 migration이 필요하다.
- **Verification:** 변경된 계약의 focused 검사와 질문→기록→후속 질문 흐름의 사례 대조.
- **Expected Output:** 관련 스킬의 최소 수정, focused 검증 결과와 알려진 한계.

### R027/S03 — 중단·변경·재개 사례 검증

- **Goal:** 사용자가 같은 설명을 반복하지 않고 필요한 기록만 읽어 이어갈 수 있는지 검증한다.
- **Scope:** 기준·스킬 정합성, 저장 완료 경계, 관련 번호와 이력 보존, 선택적 읽기.
- **Source Context:** S01 기대값, S02 결과와 아래 완료 조건.
- **Completion Criteria:** 명확한 답변 재확인, 확정 답변 재질문, 확인 전 결정 반영,
  폐기 질문의 미응답 오인, 매 세션 로그 전수 읽기를 방지하는 근거가 있다.
- **Stop Conditions:** 답변 유실·의미 변경·범위 확대가 남거나 실제 수행 없는 성공 주장만 가능하다.
- **Verification:** 답변 저장 후 중단, 해석 확인 전 중단, 사용자 교정 후 확정, Q01에 따른
  Q02 폐기와 Q01-A 추가, 단순 파생 추가, 기존 답변 번복, 맥락 충분·부족의 읽기 차이를
  확인한다. 정적 계약 검사와 실제 에이전트 동작 관찰을 구분하여 검증 한계를 기록한다.
- **Expected Output:** 사례별 결과, 필요한 회귀 검증과 문서 정합성, 잔여 위험·수락 판단 자료.

## 순서와 완료 조건

S01 → S02 → S03 구현·검증을 마쳤다. Step 결과는 Main이 수락했고, 2026-10-13 사용자가
Round 전체를 수락·클로즈했다. 스킬 교체는 전체 작업 완료 후 별도로 진행한다.
실제 근거와 한계는 Progress에서 확인한다.

- [x] 기록 대상 질답의 최초 생성과 질문별 즉시 저장이 명확하다.
- [x] 명확한 답변은 바로 저장하고 해석이 필요한 경우에만 확인 대기를 거친다.
- [x] 폐기·추가와 안정적인 파생 번호로 질문 관계·확정 답변 이력을 보존한다.
- [x] 중요성 기반 문서 생략과 필요한 경우에만 읽는 복구 경계가 명확하다.
- [x] 관련 기준·스킬 계약의 충돌을 해소하고 실제 검증 수준과 잔여 한계를 기록한다.
